# AX HD-2D implementation status

This branch is a playable fidelity pass, **not an exact or complete port of Medabots AX**. It replaces the prototype's invented movement and balance where the source evidence is established, and introduces newly generated cel-style sprites over layered Three.js environments. No ROM or emulator is needed to play.

The evidence baseline is the European Metabee release documented in [Original battle reference](original-battle-reference.md), with corrections in [Roster and mechanics evidence](ax-roster-evidence.md). Those documents distinguish source analysis, emulator measurements, and unresolved interpretations. The original reference's prototype-comparison section describes the earlier build, not this branch.

## Remaining work before claiming original-game parity

1. **Roster and equipment coverage.** The research identifies 120 usable equipment names across 30 numeric sets. This build has four assembled characters and their 16 parts, plus the fallback frame strike. The other 26 sets, their art, and unsupported abilities are not disguised as working clones. The full canonical identity crosswalk still needs verification.
2. **All mechanics.** The original 35 action types, 12 Medaforces, defensive/support/trap/status interactions, and all special movement families are not complete. Only two medals and their specials are playable. No equipment customization menu is included.
3. **AI.** The local AI is deterministic and active, with the five presented partner-panel choices, but it uses the existing utility controller and its own seeded generator. It is not the original state machine, profile tables, navigation, or shared RNG-consumption order.
4. **Attack fidelity.** Weapon-specific per-frame contact rectangles, missile motion, stagger/invulnerability durations, vulnerability predicates, and Barrage's target/angle corner cases need further work. A `verified` ability flag refers to its source timing transcription, not a certification of the entire handler.
5. **Collision edge cases.** Source-order pushing, dash-through interactions, upward actor clipping, slope/actor interactions, and platform rider flag edge cases require emulator fixtures. Existing terrain tests establish focused behavior, not an exact whole-game physics equivalence claim.
6. **Art and animation.** Four pose images per robot are a first sprite pass, not the original full animation set. Region-based broken armor is a temporary visual treatment. The environments retain collision composition and field identity, but are new interpretations rather than traced background layers. Audio remains synthesized prototype audio.
7. **Camera and local extensions.** The single-player view follows original dimensions and bounds but smooths its look-ahead. Multiple local humans use a wider shared view that follows vertical separation and widens on tall fields. Shared keyboards, controller menus, four-human play and the modern HUD typography are intentional browser extensions.
8. **Verification.** The full-jump trace is measured in the original emulator; many other cases are source-derived. Hardware gamepads still require a physical controller check. Browser tests use keyboard input; session tests cover two simulated pads and reconnection.

## Verification of this pass

- `pnpm install --frozen-lockfile`, `pnpm check`, and the five Chromium smoke tests pass.
- 75 unit/integration tests cover content, commands, movement, terrain, combat, specials and match lifecycle. The full original jump trace checks all 54 recorded positions.
- Seeded AI matches on all 19 fields reach a result and register combat hits. This checks reachability in those scenarios, not original AI equivalence.
- Additional browser playthroughs cover shared-keyboard movement, jumps and attacks on ruins, factory, polar and forest fields; controller setup and return navigation; no browser errors were recorded.
- Physical controller hardware was unavailable. Two independent pads, mixed assignments and reconnection are covered by session/input tests, not a claimed hardware playtest.

## Continue safely

Keep source facts in JSONC and record their origin here or in the reference. Add a measured/source-derived fixture before changing a delicate rule. Do not change a passing original fixture simply to preserve prototype behavior. Keep authoritative rules inside `battle-core`, sprite work inside `render`, and physical input in the local session. A future Colyseus adapter can consume the same serializable state; no networking has been added.
