# AX HD-2D implementation status

This branch is a playable fidelity pass, **not an exact or complete port of Medabots AX**. It replaces the prototype's invented movement and balance where the source evidence is established, and introduces newly generated cel-style sprites over layered Three.js environments. No ROM or emulator is needed to play.

The evidence baseline is the European Metabee release documented in [Original battle reference](original-battle-reference.md), with corrections in [Roster and mechanics evidence](ax-roster-evidence.md), [Full roster evidence](ax-full-roster-evidence.md), and [AI and weapon evidence](ax-ai-weapons-evidence.md). Those documents distinguish source analysis, emulator measurements, and unresolved interpretations. The original reference's prototype-comparison section describes the earlier build, not this branch.

## Remaining work before claiming original-game parity

1. **Roster identity and presets.** All 30 source sets are selectable, with four new art poses each. The 120 part records and medal level tables are transcribed numerical facts. Default medal assignments are observed encounter choices where available and explicit browser presets elsewhere. Four Rokusho-exclusive English names have weaker cross-reference evidence; see the roster document. Equipment customization is not exposed in the menu.
2. **Weapon and special fidelity.** All 35 action types have behavior, but this is not a frame-exact port of every handler. Friendly support delivery resolves after a logical delay instead of a simulated homing route. Plus Counter restores four ammo uses without its original interception path; Power Drain heals on impact instead of on the returning object. Question currently uses a confusion projectile approximation, and special trajectories/contact sizes and Confusion timing still need individual ports and emulator fixtures. Leg-family maneuvers are incomplete.
3. **AI.** Original profile/cooldown tables, medal group selection, Manhattan target ordering, head-ammo conservation, action eligibility, selected-slot cooldowns, attack edges, optical holds and special delay inform the new controller. AI shares the battle random byte stream through session-owned consumption metadata. Platform navigation, guard threat detection and attack spacing retain heuristics; random reads are grouped before the frame rather than interleaved with each actor's original handler. This is substantially broader AI, not a claim of original AI equivalence. The browser default partner panel targets the enemy leader.
4. **Attack fidelity.** Weapon-specific per-frame contact rectangles, missile motion, stagger/invulnerability durations, vulnerability predicates, and special target/angle corner cases need further work. A `verified` ability flag refers to its source timing transcription, not a certification of the entire handler. Current status and passive-absorption tests establish representative interactions, not all original pairings.
5. **Collision edge cases.** Source-order pushing, dash-through interactions, upward actor clipping, slope/actor interactions, and platform rider flag edge cases require emulator fixtures. Existing terrain tests establish focused behavior, not an exact whole-game physics equivalence claim.
6. **Art and animation.** Four pose images per robot are a first sprite pass, not the original full animation set. Region-based broken armor is a temporary visual treatment. The environments retain collision composition and field identity, but are new interpretations rather than traced background layers. Audio remains synthesized prototype audio.
7. **Camera and local extensions.** The single-player view follows original dimensions and bounds but smooths its look-ahead. Multiple local humans use a wider shared view that follows vertical separation and widens on tall fields. Shared keyboards, controller menus, six-human assignments and the modern HUD typography are intentional browser extensions.
8. **Verification.** The full-jump trace is measured in the original emulator; many other cases are source-derived. Hardware gamepads still require a physical controller check. Browser tests use keyboard input; session tests cover two simulated pads and reconnection.

## Verification of this pass

- `pnpm install --frozen-lockfile`, `pnpm check`, and all seven Chromium smoke tests pass.
- 111 unit/integration tests cover content, commands, movement, terrain, combat, statuses, support, specials, AI and match lifecycle. The full original jump trace checks all 54 recorded positions.
- Seeded AI matches across all 30 robots reach a result and reproduce identical snapshots/results when replayed. Separate matches on all 19 fields check combat reachability. This checks reachability in those scenarios, not original AI equivalence.
- Additional browser playthroughs cover shared-keyboard movement, jumps and attacks on ruins, factory, polar and forest fields; large desktop/mobile roster and controls, controller setup and return navigation; no browser errors were recorded.
- Physical controller hardware was unavailable. Two independent pads, mixed assignments and reconnection are covered by session/input tests, not a claimed hardware playtest.

## Continue safely

Keep source facts in JSONC and record their origin here or in the reference. Add a measured/source-derived fixture before changing a delicate rule. Do not change a passing original fixture simply to preserve prototype behavior. Keep authoritative rules inside `battle-core`, sprite work inside `render`, and physical input in the local session. A future Colyseus adapter can consume the same serializable state; no networking has been added.

The match-size/preview pass adds 1-vs-1 and 3-vs-3 browser modes, per-robot difficulty, and a readable dashboard outside the arena. These are deliberate extensions to AX, documented in [Architecture](architecture.md).
